# Validation checkpoint

Local results as of 2026-10-24. These describe tests on the development Mac and are not a guarantee for a fresh checkout, audio device, or plug-in install. Raw recordings, native sessions, screenshots, local inspection files, and private device inventory are intentionally outside this portable package.

| Area | Observed result | Remaining boundary |
|---|---|---|
| Source build and audio | The x86_64 source app ran at 48 kHz with a requested 256-frame buffer and no input device. | Other Macs, devices, and physical input are untested. |
| Clip grid | Native source playback captured one 4-bar Rhythm clip and one 8-bar Lead clip from generated tones. The tones were then switched off. A subsequent recording ran for 367.73 seconds, about 23 eight-bar repetitions, and sampled one-second RMS windows were identical across that recording. | This supports stable generated-tone playback in that run. It does not establish sample-accurate timing, glitch-free first commit, microphone capture, or guitar performance. |
| Native persistence | A `.bsk` session reopened with occupied grid cells in the stopped state and saved loop waveforms present. | Native plugin-grid reload followed by clip launch exported both 220/330 Hz components with source volumes and monitors zero. Human listening after reopen is unverified. JSON layout loading alone is not native session proof. |
| AI patch | The script builder created the native graph; transport showed 105 BPM. Postconfiguration set bass playback and the native distortion/delay controls. The file bridge handled live state reads, a bass gain change from 0.20 to 0.10 and back, a checkpoint of the prior value, and rejection of invalid requests. | No sustained bridge audio-load or restart-persistence test. The hardened client now rejects an ID that already has a result; its new test is host-side. |
| Open source VST3 | A separate x86_64 JUCE probe scanned and loaded Surge XT, Surge XT Effects, BYOD, and CHOWTapeModel. All four produced finite, nonzero audio and restored a changed parameter after state save and fresh-instance reload. | Bespoke loaded all four; generated tones were captured through BYOD and CHOWTapeModel, played through Surge Effects, saved/reopened, then exported with both frequency components and no clipped samples. Native Surge instrument MIDI performance is unverified. Surge XT Effects restored the parameter but its serialized state bytes were not identical after reload. Plug-ins are optional and not bundled. |
| Focused tests | `looper/scripts/test.sh` runs five AI script/client contract tests plus the pure `LoopGridState` and `LooperCommitMath` tests. | These tests cover state and arithmetic contracts, not the full live audio path. |

Mouse-driven UI behavior, external MIDI or guitar hardware, other audio interfaces, physical speaker acceptance, and strict real-time allocation/dropout behavior have not been verified. The stock recorder's first commit can still copy large buffers and may allocate when a new channel is first used.
